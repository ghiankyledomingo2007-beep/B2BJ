# Laboratory 6 Enemy AI

This mode implements the simple Chase AI in **Laboratory 6 - Enemy AI.pdf**.
Launch the submission JAR with:

```bash
java -jar B2BJ.jar --lab6
```

From the development checkout, build with `./build.sh`, then use
`./run-lab6.sh` for the small-heap, borderless launcher. You can also use
`java -jar build/B2BJ.jar --lab6`. Alt+F4 closes the window.

## What the instructor asks for

1. Read the player and enemy sprite centers every update.
2. Subtract the enemy center from the player center to find the direction.
3. Calculate their distance with the Pythagorean theorem.
4. Stop when the distance is greater than 300 pixels.
5. Stop when the distance is 80 pixels or less.
6. Otherwise, normalize the direction and move at 0.08 pixels per millisecond.

B2BJ measures time in seconds, so the equivalent speed is **80 pixels per second**.
Both displayed sprites are 80 by 80 pixels in this mode. The actor coordinates
refer to the top-left corner; `playerBounds()` and `enemyBounds()` supply the centers.
`Math.hypot(dx, dy)` computes the same distance as `sqrt(dx*dx + dy*dy)`.
The last movement step is capped at the remaining distance to the 80-pixel boundary.
A tiny numerical tolerance prevents diagonal floating-point rounding from keeping
the state at "CHASING" after the enemy has stopped.

## Demonstration order

1. Press **1**. At 420 pixels, the enemy stays still outside detection range.
2. Press **2**. Starting at 240 pixels, the enemy approaches at 80 pixels/second:
   following the player. It takes about two seconds to reach the stopping distance.
3. Wait. At 80 pixels, movement stops near the player.
4. Move the player with **WASD or arrow keys**. The enemy recalculates the direction
   and follows while the player remains within 300 pixels.
5. Move farther than 300 pixels away. The enemy stops immediately.
6. Press **3** to reset directly to the nearby case if needed.

**Space** pauses/resumes. **R** resets to the outside-range case.
Switching away from the window pauses and releases movement keys; press Space after
returning. The cyan slime is the player and the purple remnant is the enemy.
At the owner's request, the view keeps just the sprites and red player / blue enemy
frame rectangles and small COLLISION! / No Collision text, matching the sample video. There are no range circles,
distance readouts, grid, controls text or lab banner. The numerical rules remain
in the source and tests.

- `src/EnemyAiLab.java`: constants, `updateEnemyAI()`, `step()`, and bounds/center methods.
- `src/SlimeAnimation.java` and `src/WispAnimation.java`: existing animation timing;
  unchanged for this exercise.

The instructor's application is named `BasicSprites`; this project uses `B2BJ`.
The handout permits a separate class for more complex AI. Here, a dedicated panel
keeps the assignment's simple behavior separate from the existing game's attacks,
patrols and persistence. This mode does not load or write a campaign save.
Normal B2BJ enemies deliberately retain their gameplay settings.

## Verification

`EnemyAiLabTest` checks stationary behavior outside detection, the 300-pixel boundary,
80 px/s speed, normalized diagonal movement, frame-rate consistency, exact stopping,
coincident centers, invalid elapsed time, pause, key repeat, focus loss and presets.
It also renders all three evidence states. `build.sh` runs this alongside the
existing game tests.

After building, regenerate the deterministic captures from the project root with:

```bash
capture_classes="$(mktemp -d /tmp/b2bj-lab6-captures.XXXXXX)"
javac --release 17 -cp build/B2BJ.jar -d "$capture_classes" test/EnemyAiLabTest.java
java -ea -Djava.awt.headless=true -cp "build/B2BJ.jar:$capture_classes" EnemyAiLabTest docs/testing/lab6
```

For a short explanation: "We find both sprite centers and measure the distance.
If the player is farther than 300 pixels or within 80 pixels, the enemy stops.
Otherwise, we divide the direction by the distance and move at 80 pixels per second."
